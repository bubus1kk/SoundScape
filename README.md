# SoundScape

**SoundScape** — разрабатываемое Android-приложение для знакомства с музыкой через интерактивную карту мира. Пользователь сможет исследовать музыкальные подборки городов, находить композиции, сохранять связанные с музыкой места и вести музыкальный дневник путешествий.

Проект объединяет географию, музыку и личные воспоминания: выбранные места и маршруты связываются с реальными композициями, а ИИ помогает составлять тематические плейлисты из проверенного музыкального каталога.

> **Состояние на 7 ноября 2026 года:** серверная часть реализована и опубликована в Supabase; основные внешние интеграции работают. Практическая работа № 10 («Внешние интеграции и надёжность») выполнена. Это **не** означает готовность всего Android-приложения или прохождение полного тестирования всех сценариев.

## Возможности приложения

Ниже описан **целевой функционал SoundScape**:

- **Музыкальная карта:** интерактивная карта с редакционными подборками городов и пользовательскими музыкальными отметками в любой точке мира. Для первоначального редакционного наполнения выбраны 20 столиц.
- **Поиск и прослушивание:** поиск композиций и исполнителей, плейлисты, избранное, общая очередь воспроизведения и фоновый плеер.
- **Музыкальные отметки:** привязка существующих композиций, описания и фотографий к координатам.
- **Музыкальный дневник:** записи о путешествиях с местами, фотографиями и музыкой.
- **ИИ-плейлисты:** подборка реальных треков по запросу пользователя, фильтрам, месту или последовательности остановок.
- **Музыкальные путешествия:** объединение нескольких точек и связанного плейлиста. Их музыкальная продолжительность рассчитывается по суммарной длительности композиций, а не по времени движения между точками.
- **Публичные материалы и обмен:** профили, лайки, сохранение чужих публичных плейлистов, ссылки и QR-коды.
- **Локальные данные и функции устройства:** черновики, последующая синхронизация, места поблизости и случайное музыкальное открытие при встряхивании телефона.

Гостям предусмотрено чтение публичных материалов; для создания и изменения собственного контента необходима авторизация. Пользовательские материалы могут иметь режимы **PUBLIC**, **UNLISTED** (доступ по секретной ссылке) и **PRIVATE**.

Встроенное прослушивание предполагается только для треков, которые музыкальный источник разрешает воспроизводить в приложении. Для остальных записей предусматривается переход по проверенной ссылке во внешний сервис.  Редакционные подборки публикуются после ручного утверждения.

## Технологии

### Android-клиент — выбранный стек

| Технология | Назначение |
|---|---|
| Kotlin | Основной язык приложения |
| Jetpack Compose, Material 3 | Пользовательский интерфейс |
| Coroutines, Flow, StateFlow | Асинхронность и состояние экранов |
| Hilt | Внедрение зависимостей |
| Room, DataStore | Локальные данные, черновики и настройки |
| Retrofit, OkHttp | HTTPS-запросы к серверному API |
| AndroidX Media3 | Воспроизведение, очередь и фоновый плеер |
| MapLibre | Интерактивная карта |
| WorkManager | Фоновая синхронизация |

Для карт предварительно выбран **MapTiler**; **Яндекс MapKit** рассматривается как резервный вариант.

### Сервер и внешние сервисы

| Технология | Назначение и состояние |
|---|---|
| Supabase PostgreSQL, PostGIS | Облачная БД, географические данные; развёрнута |
| Supabase Auth | Регистрация и авторизация пользователей; рабочий вход проверен |
| Supabase Storage | Хранение файлов с серверными правилами доступа; инфраструктура создана |
| PostgREST RPC | Серверные операции чтения и изменения данных; развёрнуты |
| Supabase Edge Functions (TypeScript/Deno) | Защищённые серверные интеграции и вспомогательное API; развёрнуты |
| Audius | Поиск реальных музыкальных композиций; живой запрос из облака успешен |
| GigaChat (`GigaChat-2`) | Формирование тематических подборок; успешная генерация подтверждена |
| MusicBrainz | Дополнительные музыкальные метаданные; серверный User-Agent настроен, отдельный актуальный сквозной тест не подтверждён |


## Архитектура

Android-клиент проектируется на основе **Clean Architecture**, **MVVM** и **SOLID** с разделением на Gradle-модули.

- **Domain** — модели, бизнес-правила, use cases и интерфейсы репозиториев; чистый Kotlin без зависимостей от Android и сетевых библиотек.
- **Data** — реализации репозиториев, HTTPS, локальное хранение, DTO и преобразование данных.
- **Presentation** — Compose-экраны, ViewModel, навигация и UI-состояния.
- **Platform** — воспроизведение, геолокация, датчики и другие возможности устройства через адаптеры.

Android-клиент обращается к Supabase через **HTTPS API**, а не напрямую к PostgreSQL. Серверные секреты GigaChat и Audius не должны попадать в приложение или публичный репозиторий.

## Реализованная серверная часть

**Облачный проект:** [SoundScape в Supabase](https://supabase.com/dashboard/project/spgawlqdkzoxgrncunxg)

**Базовый URL API:**

```text
https://spgawlqdkzoxgrncunxg.supabase.co
```

**Пример настоящего API-маршрута**

```text
POST https://spgawlqdkzoxgrncunxg.supabase.co/functions/v1/v1-search-tracks
```

На сервере опубликованы:

- **7 SQL-миграций**;
- **29 прикладных таблиц** с включённой RLS и настроенными серверными правилами доступа;
- **17 пользовательских PostgREST RPC-методов**;
- **7 Edge Functions**;
- серверное файловое хранилище Supabase Storage.

Всего опубликовано **24 бизнес-эндпоинта** (17 RPC + 7 Edge Functions). Supabase Auth и стандартные служебные API в это число не входят.

### Edge Functions

| Функция | Назначение |
|---|---|
| `v1-search` | Поиск по объектам приложения |
| `v1-search-tracks` | Поиск композиций через каталог и Audius |
| `v1-resolve-track` | Определение допустимого источника композиции |
| `v1-generate-playlist` | Генерация предварительной ИИ-подборки через GigaChat |
| `v1-open-share` | Открытие материала по секретной ссылке |
| `v1-manage-share` | Создание и отзыв ссылок общего доступа |
| `v1-media` | Контролируемая выдача файлов |

Для Edge Functions используется путь:

```text
POST /functions/v1/<имя-функции>
```

### Безопасность и надёжность

- Секреты внешних сервисов хранятся в **Supabase Edge Function Secrets**, а не в клиентском коде.
- Входные данные проверяются; ошибки Edge Functions возвращаются в JSON с `code`, `message` и `requestId`.
- Для PostgREST RPC используется собственный формат ошибок PostgreSQL/PostgREST; Android-клиент должен приводить его и ошибки Edge Functions к общему представлению.
- Настроено ограничение частоты запросов. Для генерации — **5 запросов на пользователя в сутки** и **50 на проект в сутки** (суточное окно по UTC). Учитываются также попытки, завершившиеся ошибкой после резервирования квоты.
- Сервер ведёт диагностические логи с идентификаторами запросов; в логах провайдеров не должны появляться значения токенов и секретов.
- HTTPS-соединение с GigaChat настроено с дополнительным доверенным корневым сертификатом и включённой проверкой TLS.
