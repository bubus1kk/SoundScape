# Токио и Лондон

Переносимый архив BE-03. `catalog.json` содержит исторические записи и связи, локальные редакционные черновики ревизии 3 и исходные пути производственных обложек. `*-plan.json` и `*-resolver.json` относятся к живому пилоту ревизии 2. Текущий порядок зафиксирован в `manifest.json` и `catalog.json`. Позиции 1 и 2 поменялись местами. `credits.json` хранит независимые подтверждения музыкальных кредитов без изменения сырых полей. `provider-ledger.jsonl` содержит бюджеты, фактические попытки, метрики и хэши проверок.

## Автономное восстановление

1. Разверните все миграции в новом одноразовом локальном Supabase с отдельным именем проекта. Для переноса достаточно PostgreSQL. Применение к основной локальной базе и к production исключено.
2. Проверьте архив из корня репозитория командой `deno run --allow-read=backend/editorial/pilot backend/scripts/editorial-archive.ts --verify backend/editorial/pilot`.
3. Выберите случайный UUID. Подключитесь как postgres только к контейнеру нового стенда. Добавьте в пустую служебную таблицу строку `INSERT INTO internal.editorial_fixture_target(marker) VALUES ('<UUID>');`. По умолчанию `allow_live=false`.
4. Сгенерируйте SQL командой `deno run --allow-read=backend/editorial/pilot backend/scripts/editorial-archive.ts --restore-sql backend/editorial/pilot <UUID>`. Сохраните вывод как UTF-8. Примените его к тому же контейнеру через `psql -X -v ON_ERROR_STOP=1 -f <файл>`. Повтор той же команды сохраняет UUID и ревизии. Конфликт данных откатывает транзакцию.
5. Проверьте две строки `internal.editorial_drafts`, обе с 13 позициями и пустыми полями утверждения и публикации. Сверьте UUID позиций с manifest. История `verified_at` переносится без изменений.

Аудио и PNG в архив не входят. Для будущего утверждения и публикации получите оригиналы через редакторский доступ и заново подтвердите все источники, включая свежесть Audius в пределах серверного окна. Исторические статусы `IN_APP` и `EXTERNAL_ONLY` описывают день пилота. Они не подтверждают текущее воспроизведение. В production импорт выполняется штатным редакционным процессом после повторной проверки источников.
